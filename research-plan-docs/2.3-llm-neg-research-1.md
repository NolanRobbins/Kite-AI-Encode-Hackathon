### 1. Buyer / Seller / Critic Three-Agent Architecture

The system uses three distinct LLM agents, each instantiated as a subclass of a shared `DialogAgent` base class ([`agent.py`](https://github.com/FranxYao/GPT-Bargaining/blob/main/agent.py)):

| Agent | Class | Role |
|---|---|---|
| **Seller** | `SellerAgent` | Aims to sell a balloon at the highest possible price. Starts by quoting `$SELLER_INIT_PRICE` (default $20). Knows its own `cost_price` (default $8). |
| **Buyer** | `BuyerAgent` | Aims to purchase at the lowest possible price. Opens by asking for `$BUYER_INIT_PRICE` (default $10). Does not know the seller's cost. |
| **Critic** | `SellerCriticAgent` / `BuyerCriticAgent` | Observes the full dialog history of the target player (seller or buyer) and generates exactly **three actionable suggestions** to improve that player's negotiation strategy. The critic is the same LLM engine as the player it is coaching. |
| **Moderator** | `ModeratorAgent` | A fourth supporting agent (always GPT-3.5-Turbo). Invoked only when one player's response lacks a price number. Examines the last `trace_n_history` turns and classifies the game state as `YES` (deal reached) or `NO`. |

**Interaction pattern:**
- Only **one** player (seller or buyer) receives critic feedback in a given experimental run — the "rival" player resets to its initial state at the start of each new round and has no memory of prior rounds.
- This asymmetry is intentional: it isolates the improvement signal to one side.
- The critic never speaks to both players simultaneously.

**Source:** [README](https://github.com/FranxYao/GPT-Bargaining#readme), [agent.py](https://github.com/FranxYao/GPT-Bargaining/blob/main/agent.py), [arXiv paper §2](https://arxiv.org/abs/2305.10142)

### 2. Self-Play Improvement Loop

The loop is the core algorithmic contribution of the paper. It operates as follows ([arXiv §3](https://arxiv.org/abs/2305.10142)):

```
REPEAT for n_rollout rounds (up to 5 in multi-round experiments):
  1. RESET rival (buyer or seller) to initial state
  2. RUN single negotiation game (up to n_round=10 dialog turns)
       seller.call(buyer_run) → seller_run
       buyer.call(seller_run) → buyer_run
       [if no price detected] → moderator.moderate(dialog_history)
  3. RECORD deal price (or -1 for no deal)
  4. CRITIC observes the full dialog history of the coached player
       critic.criticize(player_history) → 3 suggestions
  5. INJECT feedback into coached player via receive_feedback():
       - Append critic feedback to player's dialog_history
       - Prepend goal: "buy lower than $prev_price" or "sell higher than $prev_price"
       - Add acknowledgement message (player confirms the goal)
       - Restart bargaining from the item-introduction exchange
  6. The coached player now carries: 
       - ALL prior round histories (as in-context demonstrations)
       - ALL prior critic feedback messages
       → This is ICL-AIF (In-Context Learning from AI Feedback)
```

**Key mechanism — in-context accumulation:** The coached player's `dialog_history` grows across rounds; previous full negotiations are retained as demonstrations. There is no gradient update — improvement is entirely from the model using its own prior experience and the critic's text suggestions as few-shot context.

**Scale used in experiments:**  
- Single-round experiments: 500 runs (before/after one critic feedback round)  
- Multi-round experiments: 200 runs, up to 5 feedback rounds  

**Source:** [agent.py `receive_feedback()` method](https://github.com/FranxYao/GPT-Bargaining/blob/main/agent.py), [arXiv §3–4](https://arxiv.org/abs/2305.10142)

### 3. Bid Format: Natural Language vs. Structured

Bids and prices are expressed in **free-form natural language**, embedded as dollar amounts within conversational text. There is no JSON, XML, or structured schema.

**Evidence from prompt files** ([`lib_prompt/seller.txt`](https://github.com/FranxYao/GPT-Bargaining/blob/main/lib_prompt/seller.txt)):
```
SYSTEM: You are a balloon seller bargaining with a buyer.
        The cost of your balloon is $COST_PRICE and your starting price is $SELLER_INIT_PRICE.
        You should only respond to your buyer with one short, succinct sentence.
USER:   Hi, how much is the balloon?
ASST:   Hi, this is a good balloon and its price is $SELLER_INIT_PRICE
```

**Evidence from `agent.py` — price parsing:**  
The system uses regex to extract prices from raw natural language responses:
```python
money_pattern = r'\$\d+(?:\.\d+)?'  # parse_final_price()
number_pattern = r'[-+]?\d*\.\d+|\d+'  # involve_moderator()
```
If a player's response contains **no numeric string at all**, the moderator is invoked. Final deal prices are extracted by scanning `dialog_history` in reverse order for the last `$XX` mention.

**Practical examples from paper:** `"It's a good balloon and its $20"`, `"Would you consider selling it for $10?"`, `"$16 will work for today."`, `"I will offer you this special balloon at $17."`

This design means price extraction is inherently noisy, which is why the moderator exists.

**Source:** [lib_prompt/seller.txt](https://github.com/FranxYao/GPT-Bargaining/tree/main/lib_prompt), [agent.py](https://github.com/FranxYao/GPT-Bargaining/blob/main/agent.py), [arXiv §2](https://arxiv.org/abs/2305.10142)

### 4. Game-Theoretic Concepts Applied

The paper applies and discusses the following concepts ([arXiv](https://arxiv.org/abs/2305.10142)):

| Concept | Application |
|---|---|
| **Deal-or-No-Deal** | The terminal game state is explicitly binary: `DEAL` or `NO DEAL`. The paper studies the tradeoff between maximizing deal price and maintaining a high deal success rate — as agents become more aggressive (higher/lower price demands), the no-deal rate rises. |
| **Bilateral bargaining** | Two-agent, bilateral, incomplete-information setting — each player has private information (buyer's maximum WTP, seller's cost floor are not disclosed). |
| **In-context learning from AI feedback (ICL-AIF)** | The paper frames this as a form of iterative strategy refinement analogous to reinforcement learning from human feedback (RLHF), but without gradient updates. |
| **Asymmetric improvement** | The paper shows that improvement is role-asymmetric: Claude-instant improves more as a seller than as a buyer, while GPT-4 and Claude-v1.3 improve more as buyers. |

**Notably absent:** Nash equilibrium is not invoked as a formal solution concept. ZOPA (Zone of Possible Agreement) is not mentioned by name, though the deal-price range [$10, $20] implicitly defines one (seller cost $8, buyer maximum assumed ≥ $20).

**Source:** [arXiv §1, §4–5](https://arxiv.org/abs/2305.10142)

### 5. Key Code Patterns: How a Negotiation Round Is Structured

**Core `run()` function in [`run.py`](https://github.com/FranxYao/GPT-Bargaining/blob/main/run.py):**

```python
def run(buyer, seller, moderator, n_round=10, who_is_first="seller", no_deal_thres=10):
    """Run single game."""
    buyer_run = buyer.last_response  # initialized from prompt
    start_involve_moderator = False
    deal_at = "none"
    no_deal_cnt = 0

    for _ in range(n_round):
        # 1. Seller responds to buyer's last utterance
        seller_run = seller.call(buyer_run)

        # 2. Check if moderator needed (no price in response)
        if involve_moderator(buyer_run, seller_run):
            start_involve_moderator = True

        # 3. Moderator classifies state if active
        if start_involve_moderator:
            moderate = moderator.moderate(seller.dialog_history, who_was_last="seller")
            if "yes" in moderate.lower():
                deal_at = "seller"; break
            else:
                no_deal_cnt += 1
                if no_deal_cnt == no_deal_thres: break

        # 4. Buyer responds to seller's utterance
        buyer_run = buyer.call(seller_run)
        # [same moderator check for buyer side]

    # 5. Extract final price from dialog history via regex
    if deal_at != "none":
        final_price = parse_final_price(seller.dialog_history)  # or buyer's
        return final_price
    else:
        return -1  # no deal
```

**Agent `call()` method — stateful LLM invocation:**
```python
def call(self, prompt):
    prompt = {"role": "user", "content": prompt}
    self.dialog_history.append(prompt)       # append user turn
    messages = list(self.dialog_history)     # full stateful context
    message = self.call_engine(messages)     # route to GPT/Claude/etc.
    self.dialog_history.append(dict(message))  # append assistant response
    return message['content']
```

**Critic `criticize()` method — generates three suggestions:**
```python
def criticize(self, seller_history):
    prompt = ""
    for d in seller_history[1:]:  # skip system prompt
        role = "buyer" if d["role"] == "user" else "seller"
        prompt += f"{role}: {d['content']}\n"
    prompt += "\n\nNow give three suggestions to improve the seller's negotiation strategy: "
    messages[-1]['content'] += "\n\n" + prompt
    response = self.call_engine(messages)
    return response['content']
```

**Multi-round loop in `run.py`:** The outer loop iterates `n_rollout` times. After each game, the coached player calls `receive_feedback(critic_output, previous_price)`, which appends the feedback directly to its dialog history and resets the bargaining opening exchange — all without clearing the accumulated context.

**Source:** [run.py](https://github.com/FranxYao/GPT-Bargaining/blob/main/run.py), [agent.py](https://github.com/FranxYao/GPT-Bargaining/blob/main/agent.py)

**GitHub:** https://github.com/lechmazur/pact (29 stars)

### 1. Game Structure and Scale

**Scale:** 5,000+ 1v1 head-to-head games ([README](https://github.com/lechmazur/pact#readme))

**Per-game structure:**
- **Participants:** 1 buyer vs. 1 seller (LLM agents)
- **Rounds per game:** 20
- **Per-round protocol:**
  1. Each agent sends one public message (≤100 words) — the **communication phase**
  2. Each agent submits one sealed price quote — the **bid/ask phase**
  3. **Clearing rule:** if bid ≥ ask → trade executes at the midpoint `(bid + ask) / 2`, rounded to integer (ties randomly rounded). Otherwise, no trade that round.
  4. Both agents accumulate payoff across all 20 rounds.

**Private value model:**
- Buyer holds a private **valuation** `[0..100]`; Seller holds a private **cost** `[0..100]`
- Values are drawn fresh each game from a **weighted mix of four distributions:** uniform, correlated, semi-bimodal, heavy-tailed
- Neither agent sees the other's private value

**Information structure:** All prior bids, asks, and trades are **public history** available in the next round's prompts. The current round's opponent message is visible before submitting prices. Agents never see the live book mid-round.

**Profit formulas:**
- Buyer profit per trade: `valuation − cleared_price`
- Seller profit per trade: `cleared_price − cost`
- Negative payoffs are possible if an agent trades at a loss.

**Reproducibility:** Every game is deterministically seeded; complete JSONL logs are available in the `/logs` directory ([GitHub](https://github.com/lechmazur/pact/tree/main/logs)).

**Source:** [PACT README](https://github.com/lechmazur/pact#readme), [bidding_buyer_1v1.txt prompt](https://github.com/lechmazur/pact/blob/main/prompts/bidding_buyer_1v1.txt)

### 2. Composite Model Score (CMS) — Exact Formula and Components

CMS is the **primary ranking metric** for PACT ([README](https://github.com/lechmazur/pact#readme)).

**Components:**

| Component | Definition |
|---|---|
| **Surplus Share** | A model's share of the total economic surplus (buyer valuation − seller cost) captured across all games it plays |
| **Opponent-Balanced Share (OBS)** | A model's surplus share re-weighted to control for opponent strength — prevents high scores from being inflated purely by playing weak opponents |

**Blending formula:**

```
CMS = α × OBS + (1 − α) × SurplusShare
```

Where **α is chosen from data** (not pre-set):  
1. Put both OBS and SurplusShare on a common scale  
2. Choose the α that yields the **most stable model ordering** under bootstrap resampling  
3. Also maximizes agreement in pairwise cross-matchup comparisons  
4. That single global α is then fixed and used to recompute CMS with confidence intervals

**Confidence intervals:** Reported as a grey uncertainty ribbon in the composite scoreboard visualization. Darkness of the bar is normalized to the sharpest distribution across models. The black tick marks the mean CMS.

**Secondary metrics (not primary ranking):**
- Average profit per round
- Trade frequency (fraction of rounds resulting in a trade)
- Per-round profit trajectories
- Glicko-2 leaderboard (uses a capped log-based margin multiplier: `log(profit_diff) + 1`, capped at 4×) — ranks relative skill based on who beats whom and by how much, not raw payoff

**Source:** [PACT README §Composite Leaderboard and §Benchmark Mechanics](https://github.com/lechmazur/pact#readme)

### 4. JSONL Log Format

Each game produces one JSONL file in `/logs/`. Every line is a JSON object with a `type` field. The schema version is `1.4.0`. The following event types were observed from a live log file ([`auction_190f30b2_0_20250819_102035_f98edd.jsonl`](https://github.com/lechmazur/pact/tree/main/logs)):

#### Common fields on all events:
| Field | Type | Description |
|---|---|---|
| `schema_version` | string | Log format version (e.g., `"1.4.0"`) |
| `game_id` | string | Unique game identifier |
| `type` | string | Event type (see below) |
| `model_name` | string\|null | Model responsible for the event |
| `strategy` | null | Reserved field (always null currently) |
| `log_sequence` | integer | Global monotonic event counter within the game |

### 5. Can CMS Be Adopted as an External KPI for a Negotiation Protocol?

**Yes, with straightforward adaptations.** Here is a structured assessment:

#### Why CMS is well-suited as an external KPI:

| Property | Assessment |
|---|---|
| **Opponent-balance correction** | CMS uses OBS, which explicitly controls for who you played against. This is critical for any real-world deployment where opponents vary in skill — a naive average surplus share would be gamed by selective matchmaking. |
| **Dual-objective capture** | CMS blends both raw surplus capture and relative competitive performance, reflecting the real goal: capture margin *and* close deals against skilled counterparties. |
| **Concrete and computable** | Both components (surplus share and OBS) can be computed from any logged negotiation where private valuations and deal prices are recorded — the exact fields present in the PACT JSONL format. |
| **Model-agnostic** | CMS is computed post-hoc from outcomes; it does not require access to model internals. Any negotiating agent (LLM or otherwise) can be scored. |
| **Uncertainty quantification** | The bootstrap confidence interval methodology is directly adoptable — essential for statistically defensible KPI reporting. |

#### Adaptations required for external use:

1. **Fixed α must be re-estimated** on your specific population of opponents. The PACT α is calibrated for the 30 models in that benchmark; a different agent pool changes the optimal blend.
2. **Private value observability:** CMS requires knowing both agents' private values (valuation and cost) post-hoc to compute surplus. This must be built into the logging infrastructure of any external system.
3. **Surplus definition may need extension:** In real negotiations (multi-item, multi-attribute, dynamic pricing), "surplus" must be operationalized beyond the simple `(valuation − cost)` scalar used in PACT's 1v1 double auction.
4. **Midpoint clearing rule is specific to PACT:** External systems may have different price-formation rules (e.g., first-price, alternating offers). The surplus-share computation still works; only the clearing mechanism changes.

#### Recommended adoption path:
- Use **surplus share** as the primary operational metric (easiest to compute, most interpretable).
- Use **OBS-corrected CMS** as the headline KPI for inter-model comparison reports, recomputing α from your specific agent pool via bootstrap.
- Report **trade frequency** and **avg profit per round** as secondary decomposition metrics.
- Use PACT's JSONL schema directly for logging — the `round_end.normalized_surplus` and `payoff_change.delta` fields provide all necessary ingredients.

**Source:** [PACT README §CMS, §Methodology](https://github.com/lechmazur/pact#readme)

## Cross-Project Comparison

| Dimension | GPT-Bargaining | PACT |
|---|---|---|
| **Purpose** | Research framework: study self-improvement via critic feedback | Evaluation benchmark: rank LLMs on bargaining skill |
| **Scale** | 200–500 runs per experiment | 5,000+ head-to-head games |
| **Rounds per game** | Up to 10 dialog turns per negotiation | 20 rounds, multi-turn |
| **Price format** | Free-form natural language (`$17`) | Structured XML-tagged integer (`<price>40</price>`) |
| **Scoring** | Deal price (raw dollar amount) | CMS = weighted blend of OBS and surplus share |
| **Self-improvement** | Yes — critic injects feedback between rollout rounds | No — each model plays static, no adaptation mechanism |
| **Number of agents** | 3 (buyer, seller, critic) + optional moderator | 2 (buyer, seller) |
| **Clearing mechanism** | Moderator LLM detects verbal agreement | Algorithmic: bid ≥ ask → midpoint trade |
| **Private information** | Item cost known to seller only; buyer WTP implicit | Buyer valuation and seller cost are private, logged post-hoc |
| **Models tested** | GPT-4, GPT-3.5, Claude-v1.3, Claude-instant, Jurassic-2, Cohere | 30 models across GPT, Claude, Gemini, Grok, DeepSeek, Qwen, Llama, etc. |
| **Log format** | Python dict / stdout via logger | JSONL with typed events and schema version |
| **Primary finding** | Stronger models (GPT-4, Claude-v1.3) show consistent multi-round improvement; weaker models fail to incorporate feedback | Reasoning models dominate (GPT-5 CMS 72%); large gap to non-reasoning models |
