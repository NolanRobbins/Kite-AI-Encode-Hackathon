## 2. Rubinstein Alternating Offers Model

### The Core Formula

For an infinite-horizon alternating offers game between Player 1 (offers first) and Player 2, with discount factors δ₁ and δ₂:

```
x₁* = (1 - δ₂) / (1 - δ₁δ₂)     [Player 1's equilibrium share]
x₂* = δ₂(1 - δ₁) / (1 - δ₁δ₂)   [Player 2's equilibrium share]
```

This is the **unique Subgame Perfect Equilibrium (SPE)**. Key properties:
- First-mover advantage: `x₁* > x₂*` unless δ₁ = δ₂ → 1
- More patient player (higher δ) gets more
- As both δ → 1, the SPE converges to the **Nash Bargaining Solution** [Source 5]

### Verified Computations

| δ₁ | δ₂ | P1's Share | P2's Share | 1st-Mover Adv |
|-----|-----|-----------|-----------|---------------|
| 0.90 | 0.90 | 0.5263 | 0.4737 | +0.026 |
| 0.95 | 0.80 | 0.8333 | 0.1667 | +0.333 |
| 0.99 | 0.99 | 0.5025 | 0.4975 | +0.003 |
| 0.50 | 0.50 | 0.6667 | 0.3333 | +0.167 |
| 0.99 | 0.50 | 0.9901 | 0.0099 | +0.490 |

**NegotiatorGrid insight**: When both agents are equally patient (δ₁ ≈ δ₂ ≈ 1), the SPE is nearly 50/50 — the NBS. When one agent has a shorter deadline (lower δ), they get crushed. This means **deadline management is a key strategic lever**.

### Nash Bargaining Solution (Analytical)

For bilateral price negotiation with linear utilities:

```
NBS price = α × seller_reserve + (1 - α) × buyer_reserve
```

Where α ∈ [0,1] is the buyer's bargaining power. This is **O(1) computation** — no solver needed.

| Scenario | α | NBS Price |
|----------|---|-----------|
| Symmetric | 0.5 | $0.0300/req |
| Buyer-strong (higher rep) | 0.7 | $0.0220/req |
| Seller-strong (higher rep) | 0.3 | $0.0380/req |

Confirmed: there's no `pip install rubinstein` package. The formulas are simple enough to implement directly. NegotiatorGrid needs:

```python
class RubinsteinEngine:
    """Real-time Rubinstein pricing engine for NegotiatorGrid."""
    
    def __init__(self, my_reserve: float, my_deadline: int, discount: float = 0.99):
        self.reserve = my_reserve      # BATNA price
        self.deadline = my_deadline     # Max rounds
        self.discount = discount        # Per-round discount factor
    
    def compute_spe(self, opponent_discount: float = None) -> float:
        """Rubinstein SPE: what should I offer in round 0?"""
        d1, d2 = self.discount, opponent_discount or self.discount
        my_share = (1 - d2) / (1 - d1 * d2)
        return my_share
    
    def compute_nbs(self, opponent_reserve: float, my_power: float = 0.5) -> float:
        """Nash Bargaining Solution: the fair price."""
        return my_power * opponent_reserve + (1 - my_power) * self.reserve
    
    def target_utility(self, t: float, curve: str = "boulware") -> float:
        """Time-dependent target utility level."""
        exponents = {"boulware": 4.0, "linear": 1.0, "conceder": 0.25, "hardheaded": float('inf')}
        e = exponents.get(curve, float(curve))
        if e == float('inf'):
            return 1.0
        return 1.0 * (1.0 - t ** e)
    
    def offer_price(self, t: float, zopa_low: float, zopa_high: float, 
                    curve: str = "boulware", am_buyer: bool = True) -> float:
        """Compute the offer price at time t."""
        u = self.target_utility(t, curve)
        if am_buyer:
            return zopa_low + (zopa_high - zopa_low) * (1 - u)  # Start low, concede up
        else:
            return zopa_high - (zopa_high - zopa_low) * (1 - u)  # Start high, concede down
    
    def validate_offer(self, price: float, zopa_low: float, zopa_high: float) -> dict:
        """Validate an offer against game-theoretic benchmarks."""
        nbs_price = (zopa_low + zopa_high) / 2.0
        return {
            "in_zopa": zopa_low <= price <= zopa_high,
            "distance_to_nbs": abs(price - nbs_price),
            "buyer_surplus_pct": (zopa_high - price) / (zopa_high - zopa_low) if zopa_high > zopa_low else 0,
            "seller_surplus_pct": (price - zopa_low) / (zopa_high - zopa_low) if zopa_high > zopa_low else 0,
            "pareto_efficient": zopa_low <= price <= zopa_high,  # Any deal in ZOPA is Pareto-efficient vs no-deal
        }
```

### Concession Curve Comparison (verified numerically)

```
  t    Boulware    Linear   Conceder  Rubinstein
       (e=4.0)    (e=1.0)   (e=0.25)  (1/e=0.25)
 0.00    1.0000    1.0000    1.0000    1.0000
 0.10    0.9999    0.9000    0.4377    0.4377    ← Identical!
 0.20    0.9984    0.8000    0.3313    0.3313
 0.50    0.9375    0.5000    0.1591    0.1591
 0.80    0.5904    0.2000    0.0543    0.0543
 0.90    0.3439    0.1000    0.0260    0.0260
 1.00    0.0000    0.0000    0.0000    0.0000
```

**Key discovery**: NegMAS's "Conceder" curve (`u(t) = 1 - t^0.25`) is mathematically identical to the Rubinstein concession formula `u(t) = 1 - t^(1/e)` with e=4. NegMAS's "Boulware" (`t^4`) is the dual. This means NegMAS already implements the Rubinstein concession family — NegotiatorGrid doesn't need a separate implementation.

## 3. Game-Theoretic LLM Workflows

### The Paper (arXiv:2411.05990)

From [Hua et al. 2024](https://arxiv.org/abs/2411.05990), 99 GitHub stars:

The paper designs **structured workflows** that guide LLM reasoning through game-theoretic computations:

### Workflow Types

| Workflow | Used For | Method |
|----------|----------|--------|
| **Dominant Strategy Search** | Simultaneous games | LLM iterates over payoff matrix, eliminates dominated strategies |
| **Backward Induction** | Sequential games | LLM reasons from terminal nodes backward to compute SPE |
| **Bayesian Update** | Incomplete info | LLM updates beliefs about opponent type from observed actions |
| **Nash Equilibrium Computation** | All games | LLM follows structured steps to find NE from payoff matrix |

### Key Results

| Game | Without Workflow | With Workflow | Improvement |
|------|-----------------|---------------|-------------|
| Prisoner's Dilemma (NE rate) | Sonnet: 0%, GPT-4o: 10% | Sonnet: 100%, GPT-4o: 100% | Dramatic |
| Escalation Game (NE rate) | All models: 0% | Sonnet: 90%, o1: 100% | Dramatic |
| Battle of Sexes (Pareto NE) | 60-90% | 100% across models | Solid |
| Deal-or-No-Deal (allocation) | Near-optimal with negotiation | Near-optimal + more robust | Moderate |

### Critical Finding for NegotiatorGrid

> "Following negotiation, all models except for o1 tend to adopt the pareto optimal strategy of mutual cooperation, which deviates from the Nash Equilibrium."

LLMs naturally gravitate toward Pareto-optimal outcomes during negotiation — they cooperate too much. The game-theoretic workflow forces them to be more strategically rational. For NegotiatorGrid, this means:

1. **Without a game-theoretic guardrail**, LLM-based agents will accept suboptimal deals (cooperate when they should hold firm)
2. **With NBS validation**, offers can be checked against the theoretical optimal — rejecting offers that are too far from NBS

### The Validation Architecture

```python
class NashValidator:
    """Validates LLM-proposed offers against game-theoretic benchmarks."""
    
    def __init__(self, my_reserve, opponent_reserve_est, my_power=0.5):
        self.nbs = my_power * opponent_reserve_est + (1-my_power) * my_reserve
        self.zopa = (min(my_reserve, opponent_reserve_est), 
                     max(my_reserve, opponent_reserve_est))
    
    def validate(self, proposed_price: float, t: float) -> dict:
        """Check if LLM's proposed offer is game-theoretically rational."""
        in_zopa = self.zopa[0] <= proposed_price <= self.zopa[1]
        dist_to_nbs = abs(proposed_price - self.nbs)
        
        # At time t, with boulware curve, our aspiration should be:
        aspiration = 1.0 * (1.0 - t**4.0)
        
        # Map aspiration to price (buyer case)
        target_price = self.zopa[0] + (self.zopa[1] - self.zopa[0]) * (1 - aspiration)
        
        return {
            "is_rational": in_zopa,
            "is_individually_rational": proposed_price >= self.zopa[0],
            "distance_to_nbs": dist_to_nbs,
            "distance_to_aspiration_target": abs(proposed_price - target_price),
            "recommendation": "accept" if dist_to_nbs < 0.1 * (self.zopa[1] - self.zopa[0]) else "counter",
            "override_price": target_price if not in_zopa else None,
        }
```

### How to Combine LLM + Game Theory (the NegotiatorGrid Pattern)

From ASTRA's research (prior synthesis) + Game-Theoretic LLM workflows:

```
LLM proposes offer (from reasoning about opponent, context, NL dialogue)
    ↓
Game-Theoretic Validator checks:
  1. Is price in ZOPA? (individually rational)
  2. Is price within ε of aspiration curve target? (strategically rational)
  3. Is price above my NBS threshold? (not conceding too much)
  4. Has opponent's stance justified this concession? (ASTRA stance check)
    ↓
If valid → send offer
If too generous → override with aspiration target
If outside ZOPA → reject (walk away or counter with best offer)
```

### What Gambit Is Good For (Not Real-Time)

- **Pre-negotiation**: Compute all pure NE for the discretized bargaining game to understand the strategy landscape
- **Post-negotiation**: Verify the agreement is within the set of NE outcomes
- **Tournament analysis**: Compare agent performance against theoretical optimal play
- **Demo visualization**: Show judges the NE set and where the actual deal landed
