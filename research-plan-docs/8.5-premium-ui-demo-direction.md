# Premium UI + Demo Direction

**Last updated:** April 30, 2026

## North Star

The demo should make the viewer's eye follow the trade/barter process that NegotiatorGrid offers:

```text
buyer offer -> seller counter -> convergence -> Passport Session Fit -> payment authorization -> attestation
```

This should feel like a premium autonomous procurement console, not a dense analytics dashboard or a bombastic launch page. The core visual event is the negotiated deal forming.

## Positioning

Use this line as the visual/narrative anchor:

> Passport authorizes spend. NegotiatorGrid decides whether the deal is worth paying for.

## Round Count / Barter Process

Seven rounds is a default cap, not a fixed requirement. The system can close earlier when agents agree, or run longer up to the configured cap when the trade needs more bargaining. For demo clarity:

- Use 3-5 visible rounds for the main recorded story.
- Keep 7 as an advanced/default cap visible in settings or edge-case status.
- Explain the dynamic behavior as "negotiates until agreement, timeout, or max-round policy."
- Avoid making the viewer memorize every round; make the convergence shape obvious.

## Figma / HTML Strategy

The existing static export in `dashboard/out/index.html` is useful as a reference artifact, but Figma should not simply recreate the entire current dashboard. The design target should be a tighter hero composition based on the real app:

- Keep the real chart/timeline/data relationships from the HTML.
- Remove nonessential stat/dashboard clutter from the first viewport.
- Design around the core negotiation flow: chart, round timeline, Session Fit, settlement/attestation state.
- Use Figma for composition, spacing, hierarchy, title frames, and demo shot planning.
- Implement the final look in the actual dashboard code so the recording captures a working product, not a disconnected mockup.

## First Viewport Composition

Recommended first screen:

```text
Top rail:
  Discover -> Negotiate -> Session Fit -> Settle -> Attest

Main area:
  Large price convergence chart, centered and dominant.

Right side:
  Round timeline, concise and scroll-free during the main demo shot.

Bottom strip:
  Buyer agent, seller agent, Passport Session Fit, final deal hash.
```

The viewer should immediately understand:

1. Two agents are bargaining.
2. The price is converging.
3. Passport checks the final spend.
4. The deal becomes auditable.

## Premium UI Touches To Revisit

- Procurement state rail: `Discover -> Negotiate -> Authorize -> Settle -> Attest`.
- Cinematic first viewport focused on the barter chart, not stat cards.
- Larger, smoother price convergence chart with buyer/seller paths and a clear agreement point.
- Compact round timeline with one-line offers and typed prices.
- Passport Session Fit module with `PASS`, negotiated price, remaining budget, cap, merchant, asset, and TTL.
- Live/mock infrastructure badges: `Passport MCP live`, `Passport-compatible mock`, `x402 live`, `mock facilitator`.
- Malicious seller rejection state:
  - agreed amount
  - requested amount
  - reason: `terms_hash_mismatch` or `session_policy_mismatch`
  - status: `blocked before Passport authorization`
- Before/after split screen for high-reputation vs low-reputation seller.
- Deal hash / terms hash card that visually links negotiation transcript to settlement.
- Settlement trace from Session Fit -> x402 -> DealRecord attestation.
- "Risk reduced" or "savings captured" metric after agreement.
- Demo-safe mode toggle that locks the UI into deterministic scripted data for recording.
- Clean title and closing frames:
  - title: "NegotiatorGrid"
  - close: "Authorized agent procurement for Kite Passport"
  - final line: "Passport authorizes spend. NegotiatorGrid decides whether the deal is worth paying for."

## Things To Avoid

- Do not make the first screen a marketing landing page.
- Do not overload the viewer with every metric at once.
- Do not lead with blockchain hashes or backend implementation details.
- Do not make the visual style feel like generic crypto/cyberpunk noise.
- Do not hide the barter process under stat cards.

## Acceptance Criteria

- A judge can understand the value proposition within the first 10 seconds.
- The largest visual element shows the barter/convergence process.
- The Passport Session Fit moment is visible without scrolling.
- The malicious-seller rejection is visually unmistakable but still polished.
- The app remains truthful about live vs mock infrastructure.
