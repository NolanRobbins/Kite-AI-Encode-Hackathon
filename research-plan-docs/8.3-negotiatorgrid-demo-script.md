## Judge Q&A Prep (10 Questions)

### Q1: "How is this different from Agentic Markets?"

**Answer**: Agentic Markets — third place at Kite's ETHDenver hackathon — focused on multi-chain x402 payments across Ethereum, Polygon, and Solana. What they built was a payment routing layer, not a negotiation protocol. There's no multi-round price bargaining, no opponent modeling, no game-theoretic validation, and no on-chain deal attestation. In Agentic Markets, the seller sets a fixed price and the buyer pays it. In NegotiatorGrid, the price emerges from a bilateral negotiation grounded in Nash equilibrium analysis.

The [AgenticPay benchmark](https://arxiv.org/abs/2602.06008) (Feb 2026) showed that LLM agents exhibit "substantial gaps in negotiation performance" even in simulation — our system is the first to bring that negotiation to a live blockchain settlement pipeline.

**Citation**: AgenticPay, arXiv:2602.06008; Agentic Markets, ETHDenver 2026

---

### Q2: "What happens if the agent overspends?"

**Answer**: Three layers of protection. First, the NegMAS negotiation engine enforces a reservation price, so the agent will never agree to a price above its maximum willingness-to-pay. Second, NegotiatorGrid binds the accepted terms into a typed payment intent and refuses any x402 request that changes the amount, seller, asset, or terms hash. Third, Kite Agent Passport enforces the active Session policy: remaining budget, per-payment cap, merchant restrictions, token/asset, and expiration.

This maps to the formal framework in Müller et al.'s "Agent Contracts" paper and to Kite Passport's Session/Delegation model: agent spending authority should be bounded, revocable, and auditable, not trust-based.

**Citation**: Müller et al., "Agent Contracts: A Formal Framework," arXiv:2601.08815, Jan 2026; [Kite Passport Developer Guide](https://docs.gokite.ai/kite-agent-passport/developer-guide)

---

### Q3: "How do you verify attestations?"

**Answer**: DealRecord attestations are Solidity events emitted on Kite's EVM-compatible blockchain. Anyone can verify them in three ways: (1) read the `DealRecorded` event on KiteScan using the tx hash, (2) call `getDealHistory(agentId)` on the contract to get all deals for a given agent, or (3) independently compute `keccak256(negotiation_transcript)` and verify it matches the `finalTermsHash` stored on-chain.

The attestation is as trustworthy as the Kite chain itself. Kite's testnet has processed over 32 million transactions and 546 million agent calls since February 2025, so the infrastructure is battle-tested.

**Citation**: [Kite testnet metrics](https://chainwire.org/2025/03/29/kite-ai-soars-past-546-million-agent-calls-and-4-million-users-on-testnet-phase-1/); DealRecord contract source on GitHub

### Q4: "Could this work on mainnet?"

**Answer**: Yes, with minimal changes. The x402 protocol is already live on Base mainnet, Polygon, and Solana — the [x402 whitepaper](https://www.x402.org/x402-whitepaper.pdf) reports ~200ms settlement on Base. ERC-8004 is a Draft EIP with deployed reference implementations. Our DealRecord contract is standard Solidity that deploys on any EVM chain.

Kite now presents Passport as the launched control layer for agent payments, while our demo keeps the Kite testnet/mock fallback for reliability. The negotiation engine and attestation logic are chain-agnostic; the Passport integration point is the Session/Delegation authorization boundary.

**Citation**: [x402 Whitepaper](https://www.x402.org/x402-whitepaper.pdf); [ERC-8004 Draft](https://eips.ethereum.org/EIPS/eip-8004); [Kite Whitepaper](https://gokite.ai/kite-whitepaper)

### Q5: "What would you build next?"

**Answer**: A402 — Atomic Service Channels. Li et al.'s A402 paper (March 2026) shows how to cryptographically bind payment finalization to service execution using TEE-assisted adaptor signatures. Right now, NegotiatorGrid binds negotiation to payment (Gap A), but payment-to-service delivery is still trust-based — you pay, then hope the service delivers.

A402 closes that last gap. With atomic service channels, the payment settles if and only if the service executes correctly and the result is delivered. Their benchmarks show "orders-of-magnitude performance and on-chain cost improvements over x402." Integrating A402 into NegotiatorGrid would create a full negotiate → pay → deliver → verify pipeline with cryptographic guarantees at every stage.

**Citation**: Li et al., "A402: Binding Cryptocurrency Payments to Service Execution for Agentic Commerce," arXiv:2603.01179, March 2026

---

### Q6: "Why Kite instead of Base or Solana?"

**Answer**: Kite's SPACE framework is purpose-built for agent payments:

- **S**tablecoin-native: every transaction settles in stablecoins with sub-cent fees
- **P**rogrammable constraints: spending rules enforced cryptographically via smart contracts
- **A**gent-first authentication: hierarchical identity (user → agent → session) via BIP-32 derivation
- **C**ompliance-ready: immutable audit trails with privacy-preserving selective disclosure
- **E**conomically viable micropayments: state channels achieving sub-100ms latency at ~$0.000001 per transaction

Specifically for NegotiatorGrid: Kite provides native x402 compatibility, Kite Agent Passport provides identity plus Session/Delegation controls, MCP enables agent discovery and payment tooling, and the Kite dashboard gives users an audit trail. Base and Solana would require building or integrating those control-plane pieces separately.

**Citation**: [Kite Whitepaper — SPACE Framework](https://gokite.ai/kite-whitepaper); [Kite Docs](https://docs.gokite.ai/get-started-why-kite/introduction-and-mission)

### Q7: "What about MCP security risks?"

**Answer**: Hou et al.'s MCP security survey (March 2025) identifies 16 distinct threat scenarios across four attacker types: malicious MCP server developers, external attackers, malicious users, and security flaws in the protocol itself. The most relevant risks for NegotiatorGrid are: tool poisoning (a malicious MCP server could inject misleading agent capabilities) and data exfiltration (sensitive negotiation parameters could leak through MCP tool calls).

Our mitigations: First, identity/reputation acts as a trust gate before sensitive negotiation context is exchanged. Second, Passport Sessions cap the financial exposure even if MCP routes the agent toward a bad seller. Third, NegotiatorGrid refuses payment intents that do not match the accepted terms hash. Fourth, DealRecord attestation creates an auditable trail that makes systematic exploitation detectable.

**Citation**: Hou et al., "Model Context Protocol (MCP): Landscape, Security Threats, and Future Research Directions," arXiv:2503.23278, March 2025

### Q8: "What's the latency of the full payment cycle?"

**Answer**: For the negotiation + settlement + attestation pipeline:

| Stage | Latency | Notes |
|-------|:-------:|-------|
| MCP Discovery | ~500ms | Single HTTP round-trip to Kite MCP server |
| ERC-8004 Identity Resolution | ~200ms | RPC call to Kite testnet |
| Negotiation (5 rounds) | ~3-5s | ~500ms/round (NegMAS computation ~50ms + LLM call ~400ms + network ~50ms) |
| x402 Settlement | ~200ms–2s | x402 Whitepaper reports ~200ms on Base; Kite testnet likely 1-2s (standard EVM block time) |
| DealRecord Attestation | ~1-2s | Single write transaction to Kite testnet |
| **Total** | **~5-10s** | End-to-end from discovery to attested deal |

With Kite's state channel architecture (sub-100ms per off-chain update), the settlement step could drop to under 100ms once state channels are available for x402 payments. The x402 whitepaper's benchmark of ~200ms on Base with Flashblocks demonstrates that sub-second settlement is already achievable on optimized L2s.

**Citation**: [x402 Whitepaper — 200ms settlement](https://www.x402.org/x402-whitepaper.pdf); [CryptoSlate — x402 on Base](https://cryptoslate.com/ai-agents-can-now-pay-apis-with-usdc-in-200-ms-as-coinbase-activates-x402-bazaar/); [Kite Whitepaper — sub-100ms state channels](https://gokite.ai/kite-whitepaper)

### Q9: "What's the academic basis for this project?"

**Answer**: NegotiatorGrid sits at the intersection of four active research threads:

1. **Agent payment infrastructure**: The SoK paper (Zhang et al., April 2026) systematizes blockchain A2A payments and identifies negotiation as an open problem. We implement the future direction they call for.

2. **The agent economy**: Xu (Feb 2026) proposes a five-layer blockchain architecture for autonomous agents operating as economic peers. NegotiatorGrid implements layers 2 (identity via ERC-8004), 4 (economic settlement via x402), and extends layer 4 with negotiation.

3. **LLM negotiation benchmarks**: AgenticPay (Feb 2026) shows that state-of-the-art LLMs have "substantial gaps in negotiation performance." Our game-theoretic workflow addresses this — the Game-Theoretic LLM paper shows that Nash-guided workflows improve GPT-4o's agreement rate by 57% and total negotiation reward by 71% in incomplete-information bargaining.

4. **Payment-service atomicity**: A402 (Li et al., March 2026) extends x402 with atomic service channels. Our attestation layer provides the on-chain evidence structure that A402 channels could anchor to.

**Citation**: Zhang et al., arXiv:2604.03733; Xu, arXiv:2602.14219; AgenticPay, arXiv:2602.06008; Hua et al., arXiv:2411.05990; Li et al., arXiv:2603.01179

---

### Q10: "Why a game theory + LLM hybrid instead of pure LLM negotiation?"

**Answer**: Because pure LLM negotiation is demonstrably unreliable. Hua et al.'s "Game-theoretic LLM" paper (Nov 2024) tested GPT-4o, Claude Sonnet, and Claude Opus across multiple negotiation games and found that without game-theoretic guidance, LLMs frequently deviate from rational strategies — especially as game complexity increases.

The numbers are striking. In the Deal or No Deal negotiation benchmark (top-50 hardest scenarios):

- **GPT-4o without workflow**: 63.6% agreement rate, average total reward of 7.14
- **GPT-4o with game-theoretic workflow**: 100% agreement rate (+57%), average total reward of 12.18 (+71%)
- **Claude Opus without workflow**: 47.7% agreement rate
- **Claude Opus with workflow**: 100% agreement rate (+110%)

The workflow also reduces rounds needed — GPT-4o dropped from 18.45 rounds to 4.91 rounds (73% fewer). That's both more efficient and more rational.

NegotiatorGrid uses this exact principle: NegMAS provides the game-theoretic structure (SAO protocol, aspiration strategies, Nash equilibrium validation via Gambit), while the LLM handles natural language generation and context-aware persuasion. The LLM makes the conversation human-readable; the game theory makes the outcomes fair.

**Citation**: Hua et al., "Game-theoretic LLM: Agent Workflow for Negotiation Games," arXiv:2411.05990, Nov 2024
