## 1. SAO Protocol — Exact Message Flow

**Doc Section**: Tutorial 01; `negmas/sao/mechanism.py` [Sources 1, 4]

### What SAO Means

**S**tacked **A**lternating **O**ffers — a multi-party extension of the classic Rubinstein alternating offers protocol. In each round, every negotiator either proposes or responds. An offer is accepted when ALL negotiators accept it.

### Round Flow (from `SAOMechanism.__call__`)

```
For each round (step):
  For each negotiator in round-robin order:
    1. If this negotiator is the current proposer:
       → Call negotiator.propose(state) → returns Outcome or None
       → Broadcast offer to all other negotiators
    
    2. For each OTHER negotiator:
       → Call negotiator.respond(state, source=proposer_id)
       → Returns: ACCEPT_OFFER | REJECT_OFFER | END_NEGOTIATION | WAIT | LEAVE
    
    3. If ALL negotiators responded ACCEPT_OFFER:
       → Agreement reached → negotiation ends
    
    4. If any negotiator responded END_NEGOTIATION or LEAVE:
       → Negotiation broken → ends with no agreement
    
    5. Otherwise → next proposer's turn (stacked within same round)

  After all proposers have offered in this round → advance to next step
  
Termination conditions:
  - Agreement (all accept)
  - Broken (someone ends/leaves)
  - Timeout: step >= n_steps OR wall_time >= time_limit
```

### SAOState Key Fields

```python
@define
class SAOState:
    running: bool           # Is negotiation still active?
    step: int               # Current round number (0-indexed)
    relative_time: float    # step/n_steps (0.0 to 1.0)
    agreement: Outcome      # The agreed outcome (None if no agreement)
    broken: bool            # Did someone walk away?
    timedout: bool          # Did we hit the time limit?
    current_offer: Outcome  # The offer currently on the table
    current_proposer: str   # Who proposed the current offer
    n_acceptances: int      # How many accepted the current offer
```

### ResponseType Enum

```python
class ResponseType:
    ACCEPT_OFFER = 0      # Accept the current offer
    REJECT_OFFER = 1      # Reject and wait (may counter-propose)
    END_NEGOTIATION = 2   # Walk away — no deal
    NO_RESPONSE = 3       # No response (skip)
    WAIT = 4              # Wait for more offers
    LEAVE = 5             # Leave the table
```

### SAONegotiator Interface (the two methods you must implement)

```python
class SAONegotiator:
    def propose(self, state: SAOState, dest: str = None) -> Outcome | None:
        """Generate an offer. Return None to skip."""
        ...
    
    def respond(self, state: SAOState, source: str = None) -> ResponseType:
        """Respond to the current offer on the table."""
        ...
    
    # Lifecycle callbacks
    def on_negotiation_start(self, state): ...
    def on_negotiation_end(self, state): ...
    def on_preferences_changed(self, changes): ...
    def on_round_start(self, state): ...
    def on_round_end(self, state): ...
```

### For NegotiatorGrid (bilateral case)

In a bilateral negotiation, each round has exactly 2 offers (one per agent). The trace alternates: `(step 0, buyer, offer), (step 0, seller, offer), (step 1, buyer, offer), ...` Agreement requires BOTH to accept.

## 2. Built-in Negotiator Types and Strategies

### Aspiration Curve — The Core Formula

**Source**: `negmas/negotiators/helpers.py` [Source 4]

All time-based negotiators use an aspiration curve `u(t)` where `t ∈ [0, 1]` is relative time:

#### PolyAspiration (default for all time-based negotiators)

```
u(t) = max_aspiration × (1 - t^exponent)
```

| Strategy | Exponent | Behavior |
|----------|----------|----------|
| `"boulware"` | 4.0 | Holds firm, concedes only near deadline |
| `"linear"` | 1.0 | Steady linear concession |
| `"conceder"` | 0.25 | Concedes quickly early, flattens late |
| `"hardheaded"` | ∞ | Never concedes (always at max_aspiration) |
| Custom float | any value | e.g., 2.0 for moderate boulware |

#### ExpAspiration (alternative curve)

```
u(t) = max_aspiration × (e^((1-t)^exponent) - 1) / (e - 1)
```

| Strategy | Exponent |
|----------|----------|
| `"boulware"` | 0.125 |
| `"linear"` | 0.725 |
| `"conceder"` | 4.0 |

### TimeBasedConcedingNegotiator

**Source**: `negmas/sao/negotiators/timebased.py` [Source 4]

```python
TimeBasedConcedingNegotiator(
    name="buyer",
    offering_curve="boulware" | "conceder" | "linear" | float,  # default: "boulware"
    accepting_curve=None,  # defaults to same as offering_curve
    starting_utility=1.0   # start at max utility
)
```

At each step, it:
1. Computes aspiration level `a = u(relative_time)` using the curve
2. Finds outcomes with utility ≥ `a` for itself
3. Proposes one of them
4. Accepts incoming offers with utility ≥ `a`

### NaiveTitForTatNegotiator

**Source**: `negmas/sao/negotiators/titfortat.py` [Source 4]

A modular negotiator built from components:

```python
NaiveTitForTatNegotiator(
    kindness=0.0,       # 0 = standard TFT, >0 = more generous, <0 = harsher
    punish=False,       # If True, punish partners who don't concede
    initial_concession="min" | float,  # First concession amount
    rank_only=False,    # If True, only track rank ordering, not utility values
    stochastic=False,   # Randomize offers above concession level
)
```

**How TFT works** (from source docstring):
> "This negotiator does not keep an opponent model. It thinks only in terms of changes in its own utility. If the opponent's last offer was better for the negotiator compared with the one before it, it considers that the opponent has conceded by the difference."

Components:
- **Model**: `ZeroSumModel` — assumes opponent utility = -my_utility
- **Acceptance**: `TFTAcceptancePolicy` — accept if opponent conceded as much as I did
- **Offering**: `TFTOfferingPolicy` — concede by roughly the same amount the opponent conceded

## 3. BOA Framework

**Source**: `negmas/sao/negotiators/modular/boa.py` [Sources 4, 5]

BOA = **B**idding strategy + **O**pponent model + **A**cceptance strategy — the three-component architecture from [Baarslag et al. (2014)](https://eprints.soton.ac.uk/373067/).

### BOANegotiator Constructor

```python
from negmas.sao.negotiators.modular.boa import BOANegotiator

agent = BOANegotiator(
    acceptance=AcceptancePolicy,     # A — when to accept
    offering=OfferingPolicy,         # B — what to offer
    model=UFunModel,                 # O — opponent utility model
    extra_components=[...],          # Additional GBComponents
)
```

### Available Acceptance Strategies (A)

| Class | Logic |
|-------|-------|
| `ACNext` | Accept if `u(offer) >= α × u(my_next_offer) + β` |
| `ACLast` | Accept based on my last offer's utility |
| `ACTime` | Accept after relative time threshold |
| `ACConst` | Accept if utility above constant threshold |
| `AcceptAnyRational` | Accept anything above reserved value |
| `AcceptBest` | Accept only the best outcome |
| `AcceptTop` | Accept outcomes in top k% fraction |
| `TFTAcceptancePolicy` | Accept if opponent conceded as much as I did |
| `AllAcceptanceStrategies` | Accept only if ALL child strategies accept |
| `AnyAcceptancePolicy` | Accept if ANY child strategy accepts |

### Available Offering Strategies (B)

| Class | Logic |
|-------|-------|
| `TimeBasedOfferingPolicy` | Offers based on aspiration curve over time |
| `TFTOfferingPolicy` | Reciprocal concession matching opponent |
| `RandomOfferingPolicy` | Random outcomes from the space |
| `NoneOfferingPolicy` | Never offers (passive) |
| `LimitedOutcomesOfferingPolicy` | Offers from a predefined list |
| `NegotiatorOfferingPolicy` | Delegates to another negotiator |
| `CABOfferingPolicy` | Curve-And-Best hybrid |
| `WAROfferingPolicy` | WAR (Willing And Ready) strategy |

### Available Opponent Models (O)

| Class | How It Works |
|-------|-------------|
| `FrequencyUFunModel` | Counts how often opponent offers each value for each issue. Assumes more-frequently-offered = higher utility for opponent. |
| `FrequencyLinearUFunModel` | Same as above but assumes a `LinearAdditiveUtilityFunction` structure for the opponent. Estimates issue weights from offer frequency + value frequency. |
| `ZeroSumModel` | Assumes `u_opponent = -u_self` (zero-sum). No learning needed. |
| `RankOnlyUtilityFunction` | Tracks only ordinal ranking of outcomes, not cardinal values. |

### How Frequency-Based Opponent Modeling Works

`FrequencyLinearUFunModel` (the GSmith-style model):

1. **Issue weight estimation**: Track how often opponent's offers include each issue value. Issues whose values change less across offers → higher weight for opponent.
2. **Value function estimation**: For each issue, count frequency of each value across opponent offers. More frequent = higher estimated utility for opponent.
3. **Utility reconstruction**: `U_opponent(outcome) ≈ Σ weight_i × freq_value_i(outcome_i)` where weights and frequencies are normalized.

This is the classic frequency analysis approach from the GENIUS/ANAC competition literature.

## 4. Utility Function Types

### LinearAdditiveUtilityFunction (LUFun)

```python
from negmas.preferences import LinearAdditiveUtilityFunction as LUFun
from negmas.preferences.value_fun import IdentityFun, AffineFun, LinearFun

# U(outcome) = w_price × f_price(price) + w_quantity × f_quantity(quantity) + ...
ufun = LUFun(
    values={
        "price": AffineFun(-1, bias=9.0),      # Higher price = lower utility (buyer)
        "quantity": LinearFun(0.2),              # More quantity = more utility
        "delivery_time": IdentityFun(),          # Later delivery = more utility
    },
    weights={"price": 1.0, "quantity": 1.0, "delivery_time": 10.0},  # Optional weights
    outcome_space=session.outcome_space,
)

# Normalize to [0, 1]
ufun = ufun.scale_max(1.0)
```

### MappingUtilityFunction

```python
from negmas import MappingUtilityFunction

# Any callable → utility function
ufun = MappingUtilityFunction(
    lambda x: x[0] * 0.5 + x[1] * 0.3,  # Custom formula
    outcome_space=session.outcome_space,
)
```

### Other Types

| Type | Description |
|------|-------------|
| `AffineUtilityFunction` | `U(x) = Σ w_i × x_i + bias` |
| `LinearUtilityFunction` | `U(x) = Σ w_i × x_i` (bias=0) |
| `HyperRectangleUtilityFunction` | Utility defined by hyper-volumes in outcome space |

### Value Functions for Issues

| Class | Formula |
|-------|---------|
| `IdentityFun()` | `f(x) = x` |
| `LinearFun(slope)` | `f(x) = slope × x` |
| `AffineFun(slope, bias)` | `f(x) = slope × x + bias` |

## 5. Complete Bilateral Negotiation Example

```python
from negmas import (
    make_issue, SAOMechanism,
    TimeBasedConcedingNegotiator, NaiveTitForTatNegotiator
)
from negmas.preferences import LinearAdditiveUtilityFunction as LUFun
from negmas.preferences.value_fun import IdentityFun, AffineFun, LinearFun

# 1. Define the agenda (what are we negotiating about?)
issues = [
    make_issue(name="price", values=10),          # 0-9
    make_issue(name="quantity", values=(1, 11)),   # 1-10
    make_issue(name="delivery_time", values=10),   # 0-9
]

# 2. Create the mechanism (protocol + stopping rules)
session = SAOMechanism(issues=issues, n_steps=30)

# 3. Define preferences
seller_utility = LUFun(
    values={"price": IdentityFun(), "quantity": LinearFun(0.2), 
            "delivery_time": AffineFun(-1, bias=9.0)},
    outcome_space=session.outcome_space,
).scale_max(1.0)

buyer_utility = LUFun(
    values={"price": AffineFun(-1, bias=9.0), "quantity": LinearFun(0.2),
            "delivery_time": IdentityFun()},
    outcome_space=session.outcome_space,
).scale_max(1.0)

# 4. Add agents with strategies
session.add(
    TimeBasedConcedingNegotiator(name="buyer", offering_curve="boulware"),
    ufun=buyer_utility
)
session.add(
    NaiveTitForTatNegotiator(name="seller"),
    ufun=seller_utility
)

# 5. Run and inspect
result = session.run()
print(f"Agreement: {result.agreement}")  # e.g., (9, 8, 9)
print(f"Steps: {result.step}")           # e.g., 26
print(f"Buyer utility: {buyer_utility(result.agreement):.3f}")
print(f"Seller utility: {seller_utility(result.agreement):.3f}")

# 6. Full trace
for step, negotiator, offer in session.extended_trace[-4:]:
    print(f"  Step {step}: {negotiator.split('-')[0]} → {offer}")
```

**Verified output** (from live execution):
```
Agreement: (9, 8, 9)
Steps: 26/30
Buyer utility: 0.525
Seller utility: 0.525
```

## 6. A2A Transport Compatibility — Can NegMAS Agents Go Over the Network?

### Short Answer: Not natively, but the architecture makes it straightforward.

### Why It's Easy

NegMAS negotiators interact with the mechanism through exactly **two method calls**:

```python
offer = negotiator.propose(state)        # → Outcome (a tuple)
response = negotiator.respond(state)      # → ResponseType (an int enum)
```

Both inputs (`SAOState`) and outputs (`Outcome`, `ResponseType`) are trivially serializable to JSON. The A2A wrapper pattern:

### Network-Transparent Negotiator Wrapper

```python
import json
import httpx
from negmas.sao.negotiators.base import SAONegotiator
from negmas.sao.common import SAOState, ResponseType

class A2ANegotiatorProxy(SAONegotiator):
    """Wraps a remote negotiator behind an A2A/HTTP endpoint."""
    
    def __init__(self, remote_url: str, **kwargs):
        super().__init__(**kwargs)
        self.remote_url = remote_url
        self.client = httpx.Client()
    
    def propose(self, state: SAOState, dest=None):
        resp = self.client.post(f"{self.remote_url}/propose", json={
            "step": state.step,
            "relative_time": state.relative_time,
            "current_offer": list(state.current_offer) if state.current_offer else None,
            "n_acceptances": state.n_acceptances,
        })
        offer = resp.json().get("offer")
        return tuple(offer) if offer else None
    
    def respond(self, state: SAOState, source=None):
        resp = self.client.post(f"{self.remote_url}/respond", json={
            "step": state.step,
            "relative_time": state.relative_time,
            "current_offer": list(state.current_offer) if state.current_offer else None,
            "current_proposer": state.current_proposer,
        })
        return ResponseType(resp.json()["response"])
```

### On the Remote Side (FastAPI)

```python
from fastapi import FastAPI
from negmas import TimeBasedConcedingNegotiator

app = FastAPI()
negotiator = TimeBasedConcedingNegotiator(offering_curve="boulware")
# (initialize with ufun, mechanism nmi, etc.)

@app.post("/propose")
def propose(state_data: dict):
    state = reconstruct_state(state_data)  # deserialize
    offer = negotiator.propose(state)
    return {"offer": list(offer) if offer else None}

@app.post("/respond")  
def respond(state_data: dict):
    state = reconstruct_state(state_data)
    response = negotiator.respond(state)
    return {"response": response.value}
```

### Key Considerations for NegotiatorGrid

1. **State serialization**: `SAOState` is an `attrs` class — use `attrs.asdict(state)` for serialization. Some fields (like `ufun`) are complex objects that should stay on each side.

2. **Utility function locality**: Each agent keeps its own `ufun` local (it's private information). Only offers and responses cross the wire.

3. **The mechanism can run on either side or on a neutral third party**. The `SAOMechanism` just calls `propose()` and `respond()` — it doesn't care whether those are local function calls or HTTP requests.

4. **Mapping to A2A protocol**: Each NegMAS `propose()` call maps to an A2A message with a JSON-RPC `negotiate/offer` method. Each `respond()` maps to `negotiate/respond`.

5. **Mapping to Kite MCP**: After the NegMAS negotiation concludes with an agreement, call Kite MCP `approve_payment(amount=agreed_price)` to settle.

## NegotiatorGrid Architecture Mapping

```
NegMAS Component          →  NegotiatorGrid Component
─────────────────────────────────────────────────────
SAOMechanism              →  NegotiatorGrid Protocol Engine
SAONegotiator.propose()   →  A2A message: offer
SAONegotiator.respond()   →  A2A message: accept/reject
PolyAspiration            →  Concession strategy (configurable per agent)
BOANegotiator             →  Modular agent with pluggable B+O+A
FrequencyLinearUFunModel  →  Opponent model (feed with on-chain reputation)
LinearAdditiveUtilityFunction →  Agent preferences over deal terms
SAOState.agreement        →  Input to Kite approve_payment(amount=price)
```

### Recommended Strategy Selection for NegotiatorGrid

| Agent Role | Strategy | Why |
|------------|----------|-----|
| **Buyer (cost-minimizer)** | `BoulwareTBNegotiator` | Hold firm on price, concede late — proven highest tournament scores |
| **Seller (revenue-maximizer)** | `NaiveTitForTatNegotiator` | Reciprocal — matches buyer concession, avoids deadlock |
| **Sophisticated agent** | `BOANegotiator` with `FrequencyLinearUFunModel` | Learns opponent preferences, adapts offers — best for demo "wow factor" |
