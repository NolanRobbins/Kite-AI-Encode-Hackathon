# Independent Agent Sandboxing

**Last updated:** April 30, 2026

## Goal

NegotiatorGrid should demonstrate real agent-to-agent negotiation, not a scripted reading of a prewritten trade. For production, buyer and seller agents must be isolated decision makers with bounded authority and typed protocol messages between them.

## Current Implementation Reality

The demo is not a static 7-line script:

- The API accepts `max_rounds` from 1 to 50.
- The executor creates separate buyer and seller configs: reservation price, opening price, strategy, bargaining tendency, reputation, and NegotiatorGrid enablement.
- The NegMAS `SAOMechanism` runs separate `BuyerNegotiator` and `SellerNegotiator` instances.
- Each side independently proposes/responds using its own reservation bounds and concession curve.
- Opponent modeling is side-specific and can be enabled/disabled per agent.
- The run terminates on agreement, timeout, or max-round policy.

Seven rounds is the default policy cap, not a fixed flow.

## Production Sandbox Model

For production, treat buyer and seller as separate actors:

```text
Buyer Agent Sandbox
  - buyer policy
  - buyer reservation price
  - buyer private context
  - no seller secrets
  - no direct wallet spend

Typed Negotiation Bus
  - offer
  - counteroffer
  - accept/reject
  - terms hash
  - signed/payment intent handoff

Seller Agent Sandbox
  - seller policy
  - seller reservation price
  - seller private context
  - no buyer secrets
  - no authority to change accepted deal
```

NegotiatorGrid is the orchestrator and guardrail layer. It should not let free-text LLM output mutate typed deal fields.

## Demo Messaging

Say this plainly:

> The buyer and seller are independent negotiation policies. They exchange typed offers, not hidden shared state. NegotiatorGrid enforces the rules of the market: round caps, reservation bounds, Nash drift checks, terms hashes, Passport Session Fit, and payment refusal on mismatch.

## What To Show In The UI

Add a compact **Agent Isolation** panel:

- Buyer sandbox: independent policy, private reservation, no seller secrets.
- Seller sandbox: independent policy, private floor, no buyer secrets.
- Negotiation bus: typed offers only.
- Authority boundary: LLM prose cannot execute payment; Passport authorization requires typed intent.

## Future Production Hardening

- Run each agent in a separate worker process or container.
- Give each sandbox a scoped network allowlist.
- Do not pass `.env`, wallet keys, Passport tokens, or private reservation prices to the LLM.
- Store private buyer/seller strategy state separately.
- Require typed JSON-schema validation for every offer/counteroffer.
- Hash the accepted transcript before payment authorization.
- Use Passport Sessions and Delegations for spend authority.
- Log all negotiation events for audit and replay.

## Acceptance Criteria

- The demo can prove rounds are generated by independent policies, not a fixed transcript.
- The UI shows buyer/seller separation without overwhelming the barter visual.
- The payment path is visibly outside agent prose: `typed terms -> Passport Session Fit -> x402`.
- Malicious price mutation is blocked before payment authorization.
